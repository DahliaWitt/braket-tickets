# `testing_functions.ts` caller migration codemod

Rewrites all callers away from the `testing_functions.ts` god file onto the
per-domain paths that replace it:

```
api.testing_functions.seedEvent          → api.testing.events.seedEvent
internal.testing_functions._getByEmailInternal
                                         → internal.testing.users._getByEmailInternal
```

The function name is preserved; only the module path under `testing_*`
changes. The canonical name→domain table lives in
[`testing-functions-map.ts`](./testing-functions-map.ts) (62 entries).

## Prerequisites

The codemod and its test import [`ts-morph`][ts-morph]. Install it as a
workspace devDependency before running anything here:

```bash
pnpm add -D -w ts-morph
```

`ts-morph` gives us a real TypeScript AST and saves us from regex false
positives on things like string literals, template strings, type-reference
positions, and comments. The trade-off is a ~5MB devDependency added to the
repo lockfile for the lifetime of the migration. Remove it once the god file
has been split and all callers have been migrated.

[ts-morph]: https://ts-morph.com/

## Running the codemod

Default scope: `.ts` / `.tsx` files under `backend/`, `frontend/`, and
`scripts/`. Excludes `node_modules/`, `_generated/`, `dist/`, `build/`,
`.convex-local/`, `.angular/`, `.next/`, `coverage/`. Never touches
`backend/convex/testing_functions.ts` itself.

### Dry-run (default)

```bash
pnpm tsx backend/scripts/codemods/testing-functions-migration.ts
```

Prints per-file diffs and a summary. Exits non-zero if the run found unknown
names or dynamic accesses that need manual review.

### Write

```bash
pnpm tsx backend/scripts/codemods/testing-functions-migration.ts --write
```

Writes rewrites to disk. Commit any changes the codemod produces on a branch
so you can inspect them with `git diff` before merging.

### Other flags

| Flag                 | Behavior                                                                                     |
| -------------------- | -------------------------------------------------------------------------------------------- |
| `--dry-run`          | Default. Print diffs, write nothing.                                                         |
| `--write`            | Apply rewrites to disk.                                                                      |
| `--verbose`          | Per-file output including no-op files.                                                       |
| `--paths <glob>`     | Limit scope. Repeatable. Overrides the default set when provided.                            |
| `--allow-unknowns`   | Exit 0 even when unknown names or dynamic accesses are found (still printed for visibility). |

### Typical workflow

```bash
# 1. Add ts-morph to the repo.
pnpm add -D -w ts-morph

# 2. Dry-run on the full repo, eyeball the diff and the unknowns/dynamic
#    reports.
pnpm tsx backend/scripts/codemods/testing-functions-migration.ts

# 3. If the report is clean, commit staging changes, then apply the
#    rewrite for real.
pnpm tsx backend/scripts/codemods/testing-functions-migration.ts --write

# 4. Verify the working tree.
pnpm validate
```

## What the codemod handles

| Pattern                                                      | Action                                                                                |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------------- |
| `api.testing_functions.<Name>`                               | Rewritten to `api.testing.<domain>.<Name>` when `<Name>` is in the map.               |
| `internal.testing_functions.<Name>`                          | Same, for `internal.`.                                                                |
| `const {seedEvent} = api.testing_functions`                  | Rewritten to `const {seedEvent} = api.testing.events` when all destructured names share one domain. |
| `const {seedEvent, seedTicket} = api.testing_functions`      | Reported as a dynamic/mixed-domain access and left unchanged (cannot rewrite safely). |
| `api.testing_functions[someVar]`                             | Reported as a dynamic access and left unchanged.                                      |
| `api.testing_functions.seedSomethingNotInMap`                | Reported as an unknown and left unchanged.                                            |
| `backend/convex/testing_functions.ts`                        | Skipped (the source file; deleted by a later migration step).                         |
| `backend/convex/_generated/api.d.ts` and siblings            | Skipped (regenerated by Convex).                                                      |

## Exit codes

| Code | Meaning                                                                 |
| ---- | ----------------------------------------------------------------------- |
| `0`  | No issues, or issues reported with `--allow-unknowns`.                  |
| `1`  | Unknown names or dynamic accesses reported, and `--allow-unknowns` was not passed. |
| `1+` | Thrown error during run (stack trace in stderr).                        |

## Rollback

The codemod writes files in place — there is no built-in undo. Safe rollback
depends on the version-control checkpoint you took before `--write`:

- **Preferred:** run the codemod on a topic branch. If anything looks wrong,
  `git restore .` or delete the branch. Do not run `git reset --hard` — this
  repo has a policy against destructive git operations without explicit user
  permission (see `CLAUDE.md`).
- If you ran `--write` on an uncommitted working tree and want to undo without
  a git reset, run the codemod against the post-migration `testing/<domain>/`
  paths would be required — which is out of scope for this tool. Commit before
  running `--write`.

## Adding a new registered export

If a new registered export is added to `testing_functions.ts` before the split
is complete:

1. Add `<Name>: '<domain>'` to `TESTING_FUNCTIONS_DOMAIN_MAP` in
   [`testing-functions-map.ts`](./testing-functions-map.ts).
2. Update the test count assertion in
   [`testing-functions-migration.test.ts`](./testing-functions-migration.test.ts)
   if you changed the total.
3. Re-run `pnpm --filter backend test -- scripts/codemods` to confirm.

## Testing the codemod

```bash
pnpm --filter backend test -- scripts/codemods
```

Fixtures live in `__fixtures__/`. The test uses the pure `rewriteSourceText`
entry point for property-access and destructuring cases, and the full `run()`
harness (with injected `listFiles` / `readFile` / `writeFile`) for
filesystem-scoped behavior such as the explicit skip of
`backend/convex/testing_functions.ts`.

## Teardown after migration

This tool and its dependencies are scaffolding for a one-time migration. Once the split lands and `testing_functions.ts` is deleted, remove everything.

Checklist to run AFTER the decomposition PR is merged and CI is green:

- [ ] `pnpm remove -D -w ts-morph` — remove the devDependency added for this codemod.
- [ ] `rm -rf backend/scripts/codemods/` — delete the codemod script, map, test, fixtures, and this README.
- [ ] Verify `grep -r "testing_functions" backend frontend scripts` returns zero matches (including no stale references in `docs/`).
- [ ] Confirm `pnpm-lock.yaml` no longer lists `ts-morph` and commit the lockfile update.
- [ ] Run `pnpm validate` on a clean branch to confirm the teardown itself did not break anything.

The codemod had one job: mechanically rewrite 1421 callsites once. After the migration, it is dead weight.

## Design notes

- **AST over regex.** An earlier draft used regex replacements. Regex made it
  hard to tell whether `api.testing_functions.seedEvent` inside a type
  reference, a string literal, or a comment was safe to rewrite. ts-morph
  resolves all of those edge cases for free at the cost of a devDependency.
- **Two-pass traversal.** Pass 1 rewrites the three-hop
  `api.testing_functions.<Name>` form. Pass 2 handles the remaining two-hop
  `api.testing_functions` / `internal.testing_functions` forms
  (destructuring, dynamic index). Keeping the passes separate makes the
  node-parent logic readable without re-entrant AST state.
- **Edits applied end-to-start.** ts-morph allows in-place mutation, but
  mutating within a traversal invalidates descendant nodes. Collecting edits
  and applying them from the end of the file keeps positions valid.
- **Single source of truth for the map.** The domain map lives in a typed
  `as const` so downstream tooling (future tree-shakers, a splitter that
  scaffolds the `testing/<domain>.ts` files) can import the same table.
